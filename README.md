# Лабораторная работа 4 — Коллекции и анализ бизнес-данных

Продолжительность: 6 академических часов. JDK 25, IntelliJ IDEA, Maven, JUnit 5.

## Работа в IntelliJ IDEA

1. Получите ссылку на стартовый репозиторий у преподавателя. На экране приветствия
   выберите **Get from VCS**; в открытой IDE — **File → New → Project from Version Control**.
   Вставьте ссылку и нажмите **Clone**. Если проект выдан архивом, распакуйте его и
   откройте папку с `pom.xml` через **File → Open**.
2. В **File → Project Structure → Project** выберите JDK 25. Дождитесь загрузки
   зависимостей. При предложении IDEA нажмите **Load Maven Changes**.
3. Реализуйте восемь TODO в `SalesAnalyzer.java`. Проверки аргументов уже готовы.
   `Sale`, `DemoData`, `Application`, `pom.xml` и тесты изменять не требуется.
4. Запускайте тесты через зелёный треугольник у класса тестов. Для всех тестов:
   правый клик по `src/test/java` → **Run 'All Tests'** (название может отличаться).
5. Запускайте `Application.main` зелёным треугольником. Сверьте результаты с методичкой.
6. Если открыли архив, включите **VCS → Enable Version Control Integration → Git**.
   В **Git → Manage Remotes** проверьте или добавьте адрес своего репозитория по схеме
   преподавателя. Сохраните изменения через **Commit**, затем **Git → Push**.
   В первом коммите из архива включите `pom.xml`, `src`, `README.md` и `.gitignore`.
   Покажите преподавателю программу, тесты и файлы на сайте.

В стартовом проекте тесты, вызывающие TODO, не проходят — это ожидаемо.
После выполнения задания должны пройти **46 тестов** в восьми классах.

## Задание

| Метод | Результат |
|---|---|
| `filterByPeriod` | Продажи за период включительно, в исходном порядке |
| `findByProductCode` | Все продажи с точным совпадением кода товара |
| `sortByAmountDescending` | Новый список по сумме по убыванию, при равенстве — по id по возрастанию |
| `uniqueCustomerCodes` | Set кодов покупателей без повторений |
| `groupByCategory` | Map категория → список продаж в исходном порядке |
| `totalAmountForPeriod` | Общая сумма продаж за период |
| `amountByCategoryForPeriod` | Map категория → сумма продаж за период |
| `amountByDateForPeriod` | Map дата → сумма продаж за период |

Используйте Stream API в `filterByPeriod`, `groupByCategory` и трёх методах
расчёта сумм. Остальные методы можно написать через цикл или Stream API.
Тесты проверяют результат, а использование Stream API нужно показать преподавателю в коде.

## Правила

- Список не изменяется. Результаты-коллекции — самостоятельные контейнеры.
  Объекты `Sale` неизменяемы; создавать их копии не нужно.
- Пустой список допустим. Нет результатов: пустая коллекция или сумма 0.
- `null` вместо списка или его элемента, неверный период и пустой код товара
  приводят к `IllegalArgumentException`; эти проверки уже реализованы.
- Начальная и конечная даты входят в период; равные даты допустимы.
- Код товара сравнивается через `equals`, с учётом регистра, без обрезания пробелов.
- Порядок ключей Map и элементов Set не задан; внутри групп порядок сохраняется.
- Повторяющиеся записи не удаляются при поиске, группировке и суммировании.
- Сумма продажи — `unitPrice * quantity`. Внутри методов не округляйте `double`.
  В выводе Application суммы форматируются до двух знаков.
- В итоговых Map есть только категории и даты с продажами в периоде. Продажа с
  нулевой суммой всё равно создаёт соответствующий ключ. Дни без продаж не добавляются.

Контрольный период: 2026-09-01 … 2026-09-05. Продаж: 8; сумма: 1240.00.
По категориям: Office 190.00, Electronics 600.00, Furniture 450.00.
По дням: 70.00, 500.00, 460.00, 150.00, 60.00 соответственно.

Полные пояснения, таблица данных, ожидаемый вывод и порядок сдачи — в методических указаниях.
